## 2. Verification — every record of all 86 files

Checks per record: decoded length = directory raw_size; decoder stops exactly at comp_size (no overshoot, no slack); records contiguous from data-area offset 0 in directory order and the last one ends at EOF (no gaps, overlaps or trailers).

## 2a. Round-trip — byte-identical re-encode (method: re-compress + re-pack)

`dax.py roundtrip DIR` decodes each record, re-encodes it with `rle_encode`, rebuilds the whole file from the directory (ids, order, offsets) and the new blobs, and compares bytes. **Result: 824/824 records and 86/86 files byte-identical.** The SSI encoder rules were recovered from the bytes (search over variants, scratch script; not from code — the encoder is not in the game):

- run of ≥ 2 equal bytes → repeat token (`0x100 − n`, n ≤ 127);
- other bytes → literal tokens of at most **126** bytes (`0x7D`; never the decoder's max 127);
- the **final** run of a record is always a repeat token, even a run of 1 (`FF xx` where a literal `00 xx` would be the same length).

Variants tested (min repeat 2/3 × max literal 126/127 × max repeat 126/127 × final-repeat on/off): only (2, 126, 127, on) gives 824/824; next best 793. Cross-check on Pool's data (`re-targets/goldbox/por/POOLRAD`): **1245/1245 records, 113/113 files byte-identical** with the same encoder — one SSI packer for both games (H).

Byte evidence: `8X8D1.DAX` id 201 ends `…fd 55 fc 00 00 ff fd aa ff 00` (final single 0x00 as `ff 00`); `8X8D2.DAX` id 1 literal token `7d` (126 bytes) at record offset 287 followed by a new token where a 127-literal was possible.
